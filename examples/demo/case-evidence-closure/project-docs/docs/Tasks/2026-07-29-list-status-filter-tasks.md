# todo list 状态筛选 · 轻量任务台账

> 类型：轻量任务台账（本轮不写 OpenSpec 三件套）
> 依据模板：`skills/task-planning.md`
> 日期：2026-07-29
> 上游：[需求 brief](../Requirements/2026-07-29-list-status-filter-brief.md)

本轮走轻量模式，计划的作用由这张台账承担：**省的是文档形态，不是判断**。每项都有可核对的完成标准，不靠「做完了」三个字收口。

| # | 任务 | 完成标准 |
|---|------|----------|
| T1 | CLI 参数解析：在已有的 `--file` 扫描循环里增加 `--status` 分支 | `--status` 可出现在子命令前后；缺值报错退出 2；取值不在 `pending\|done\|all` 内时打印含可选值的错误并以非 0 退出；默认值为 `all` |
| T2 | `list` 过滤逻辑：按 `--status` 取值决定渲染哪些分区 | 沿用 `cmd_list` 已有的 done 位分区判定，只在外层加渲染开关，不另写一套判定；持久化格式 `id\|done\|title` 未改动 |
| T3 | 测试：扩充 `app/test-todo.sh` | 6 条断言，覆盖 brief 的 5 个场景；筛选类断言必须带「不包含另一类」的负向条件；输出末行 `verify passed: 6/6 checks`，退出码 0 |
| T4 | 合规审查：产出独立落盘的审查报告 | `Reviews/` 下有独立报告文件，含场景覆盖、B4、B5 与验证证据匹配度；报告中的断言编号与 `test-todo.sh` 实际一致 |
| T5 | 文档与收口：案例 README、收口清单、经验候选 | README 首屏能一条命令跑起来并说清为什么不写 OpenSpec；收口清单链接审查报告路径而非只写状态；经验候选标注为「未写入公共经验库」 |

## 边界

- 台账不替代规范：验收标准在 brief 的 Given/When/Then 里，这里只管「做到什么程度算完成」。
- 什么时候该升级到完整模式并写 OpenSpec 三件套？触发 schema 变更、权限、数据写入路径，或需要留正式审查记录时——本需求都不触发。
