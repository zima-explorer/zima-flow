# 外部 proto-gen 后续参考

> 来源：`https://github.com/xieluoli/proto-gen`，临时只读查看 commit `59371f454f3cc6f4b6d624e62b54fbb0a1e67e24`。
> 状态：仅作为后续参考；当前不安装、不复制外部 skill、不引入其资产。

## 可学习点

1. **三段结构契约**
   - 左侧 TOC：页面 / 状态索引
   - 中间原型：每个 section 一个可视化状态
   - 右侧 PRD 面板：每个 section 一组旁注
   - 价值：评审时能把页面状态、可视区域和说明一一对应。

2. **section 编号与变体规则**
   - 主页面用 `页面-01 / 页面-02`
   - 同一页面的编辑态、删除态、错误态用变体编号
   - 价值：评审者能顺着主流程读，也能跳读特殊状态。

3. **PRD 旁注写法**
   - 按视觉顺序写：顶部控件 → 主内容 → 操作按钮 → 弹窗 / 抽屉
   - 一个元素一条说明
   - 用产品语言描述，不写代码语言
   - 重复结构首个 section 完整描述，后续只写差异。

4. **PRD ↔ 原型双向高亮**
   - 通过 `data-comp` / `data-target` 将旁注 bullet 与原型组件绑定
   - 价值：评审时快速定位说明对应的界面元素
   - 风险：这是评审脚手架，进入研发实现时必须剥离。

5. **主题和组件资产分层**
   - `theme.css` 作为主题 token 单一来源
   - `shared.css` 保存组件骨架
   - `components.html` 作为人类可视组件库
   - 价值：减少每次原型手写样式的成本。

6. **自包含交付思路**
   - 原型 HTML 可以通过注入脚本把主题、组件样式和评审 JS 注入为单文件
   - 价值：评审传递方便，打开成本低。

## 当前暂不采用

- 不复制外部 `assets/`，避免主题、组件和脚本成为 zimaflow 的维护负担。
- 不引入 tweakcn 主题切换脚本，当前 zimaflow 重点是流程编排，不是视觉系统生成。
- 不默认使用 macOS 窗口外壳，项目原型应优先对齐真实业务产品形态。
- 不把高亮脚手架作为必选能力；后续如果原型评审频率高，再考虑加入。

## 已吸收到 proto-review v0.1.1

- 推荐三栏结构契约：左侧导航、中间原型、右侧 PRD 旁注。
- section 编号规则：主页面、同页变体、空态 / 权限态分开表达。
- PRD 旁注写法规范：产品语言、视觉顺序、一个元素一条、重复结构只写差异。
- 评审脚手架剥离原则：如临时使用高亮属性或脚本，必须注明不得进入生产代码。

## 已吸收到 proto-review v0.2 的流程增强

- 多页原型在 `review-notes.md` 中维护页面 / 状态—跳转清单，并允许符合条件的单页演示明确豁免。
- 原型变更先判局部或全局影响，列出受影响 section 与复验项，再更新 HTML、旁注和验收记录。
- 交付验收区分硬性检查与人工评审，并记录视觉依据；项目已有默认主题时可沿用，不以 AI 猜测替代依据。

## 已吸收到 proto-review v0.3 的流程增强

- 变更影响与复验补充“变更原因”记录，新增“保留项”清单（防止全量重生成覆盖人工修正）与“变更前快照”（改动前归档 `prototype.html` / `review-notes.md`，命名和归档位置固定，验收失败时回退的是原型产物，不回退 `proto-review/SKILL.md` 本身或上游需求契约）。
- 交付验收记录拆分为 AI 预检结果 / 运行环境复核结果 / 人工最终裁决结果三栏，并显式声明 AI 预检结果通过不等于原型验收通过。
- 页面 / 状态—跳转清单增加“来源需求”字段，支持需求变更反查受影响页面、页面问题反查需求出处的双向追溯。
- 新增“平台规范”小节：PC Web 可引用项目已配置的 Web 规范 / 设计系统；App / 小程序须结合平台组件规范与真实设备走查，不把 H5 能打开等同于原生端已验证。

这些增强只补可追溯的评审流程，**不把它扩展成原型工程生成器**：仍不加入多文件 CSS、mock 数据、组件资产、注入脚本或外部 skill。

## 仍可评估的后续候选

- 增加可选的 `data-comp` / `data-target` 高亮约定，并明确研发剥离清单。
- 为项目维护可选的 `Prototypes/components.html`，沉淀常用业务组件。

## 安全与引入规则

如未来要安装或复用外部 `proto-gen`：

1. 先走本知识库的外部 skill 标准流程：`skill-installer`。
2. 再走 `security-review`，审查脚本、依赖、网络请求、主题提取脚本、注入脚本和许可证。
3. 通过后再决定是安装原 skill、抽取参考资产，还是继续维护 zimaflow 自有 `proto-review`。
